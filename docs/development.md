# Разработка Clepsydra

Подробности, которым не место в README: как устроен круг, откуда берутся
картинки, чем собирается бандл и что нужно, чтобы раздать сборку другим.

## Как это работает

Иконка песочных часов в меню-баре, в меню — «Запустить сессию». Дальше рядом с
иконкой тикает отсчёт.

Когда 25 минут кончились, звучит сигнал и на всех мониторах разворачивается
тёмный экран с мыслью Сунь-Цзы, Марка Аврелия, Сенеки, Эпиктета, Лао-цзы или
Монтеня — и одной кнопкой «Отдохнуть». Экран поверх всего, включая чужой
полноэкранный режим, и не закрывается ни Esc, ни Cmd+W, ни Enter: выход —
клик по кнопке или запасная комбинация **⌘⇧0**, подсказка к которой написана
прямо на экране.

Нажали — экран остаётся, но кнопка уступает место отсчёту: `04:12`, `04:11`.
Встали, налили кофе, посмотрели в окно. Хотите вернуться к работе раньше —
**⌘⇧0** убирает экран, а перерыв продолжает идти и досчитывает в меню-баре,
где к этому времени появилась чашка.

Когда перерыв кончился, экран возвращается с другой цитатой и двумя кнопками:
«Начать» — следующий помидор, «Хватит» — выйти из круга.

Идущий помидор или перерыв отменяется пунктом «Сбросить». Паузы нет
(см. [ADR-0003](adr/0003-no-pause.md)).

## Режим Стетхема

Переключатель в меню меняет содержимое экрана: вместо Сенеки и Марка Аврелия —
пацанские цитаты наклейками, каждая строка своей плашкой. Собрано так же, как
философский экран: фигура сверху, текст под ней, кнопка внизу — одной колонкой
по оси. Круг, длительности, кнопки, отсчёт и ⌘⇧0 остаются теми же.

Имени на экране нет: реплики никому не приписаны, название режима живёт в меню.

Фотографий в репозитории нет — это снимки реального человека, права на них не
наши. Положите свои PNG в `Resources/statham/`, и `build.sh` заберёт их в бандл.
Без файлов режим работает и показывает наклейки без фигуры.

Фон нужен **прозрачный**: белый кант считается из альфа-канала, иначе получится
прямоугольник с каймой. Снять фон пакетом:

```bash
swift Tools/remove-background.swift Resources/statham/*.png
```

Скрипт работает через Vision — тот же механизм, что у «Удалить фон» в
Просмотре, — и перезаписывает файлы, обрезая их по контуру фигуры. Оригиналы
стоит отложить заранее: `Resources/statham-originals/` в `.gitignore` как раз
для этого.

Если Mac уснул и срок вышел без вас, интервал молча отменяется — показывать
«пора отдохнуть» через час после закрытия крышки нелепо
(см. [ADR-0002](adr/0002-overdue-interval-is-cancelled.md)).

## Портреты философов

Философский режим показывает портрет автора цитаты, если файл найден: чёрно-белый
и приглушённый, без канта и тени — противоположность наклейке.

Кладите PNG в `Resources/philosophers/`, имя файла — латиницей по автору:

| Автор | Файл | Цитат |
|---|---|---|
| Сунь-Цзы | `sun-tzu.png` | 10 |
| Марк Аврелий | `marcus-aurelius.png` | 10 |
| Сенека | `seneca.png` | 10 |
| Эпиктет | `epictetus.png` | 8 |
| Лао-цзы | `lao-tzu.png` | 8 |
| Монтень | `montaigne.png` | 4 |

Сопоставление живёт в `Quotes.portraits`; тест следит, чтобы у каждого автора
был файл и чтобы лишних записей не завелось. Файла нет — цитата покажется одна
на чёрном, как раньше.

## Появление экрана

Окно чернеет за 0,3 секунды, содержимое въезжает уже по черноте — иначе
движение было бы видно сквозь полупрозрачный экран поверх рабочего стола.

Движение разное в двух режимах. Наклейку **шлёпают**: фигура и плашки приходят
крупнее нужного, с перекрученным наклоном, и садятся с перелётом; строки по
очереди через 70 мс. Цитату философа **проявляют**: портрет, текст и автор
всплывают снизу без масштаба и перелёта. Кнопка в обоих случаях приходит
последней и без движения — по едущей кнопке легко промахнуться.

Системная настройка «Уменьшить движение» оставляет одно проявление.

## Иконка

`Resources/Clepsydra.icns` собирается из мастера `Resources/icon-source.png` —
квадрат 1024 с прозрачностью, предмет внутри занимает 824 точки, как тело
системных иконок:

```bash
./Tools/make-icns.sh
```

Каждый размер пересчитывается из мастера, а не давится из соседнего: в `.icns`
они и так лежат отдельными картинками.

Если исходник пришёл с ровным фоном, его снимает

```bash
swift Tools/trim-background.swift вход.jpg Resources/icon-source.png
```

Заливка от краёв, а не Vision: она не трогает однотонные участки внутри
предмета и возвращает полупрозрачным пикселям кромки их цвет — иначе по краю
остаётся серая бахрома.

## Сборка

Нужны Mac на Apple Silicon с macOS 14 и Command Line Tools
(`xcode-select --install`); полный Xcode не требуется.

```bash
git clone https://github.com/ilya-pesterev/clepsydra.git
cd clepsydra
./build.sh
```

Пересобирает `Clepsydra.app` — чистый arm64, подписанный ad-hoc. Перед сборкой
прогоняются тесты. Первая сборка требует сети: SwiftPM скачивает готовый
`Sparkle.xcframework`, которым ставится обновление, — дальше он лежит в
`.build/`. Собранный бандл кладут в «Программы» и запускают оттуда:

```bash
cp -R Clepsydra.app /Applications/ && open /Applications/Clepsydra.app
```

Первый запуск такой сборки macOS остановит — она подписана ad-hoc; путь через
«Все равно открыть» описан в [docs/install.md](install.md).

## Номер сборки

Номер сборки — момент сборки по UTC в виде `20260904153012`: он растёт сам,
читается как дата, и `build.sh` подставляет его в `CFBundleVersion` бандла
через `Tools/build-number.sh`. В `Resources/Info.plist` вместо номера ноль:
константа в репозитории у двух разных сборок одинаковая, а править её руками —
ровно тот шаг, который забывают.

Человеческая версия `CFBundleShortVersionString` остаётся `1.0` и от номера не
зависит; «О программе» показывает обе — «Версия 1.0 (20260904153012)».

## Тесты

```bash
swift run ClepsydraTests
```

Проверяют автомат состояний: переходы по времени, сброс, «Хватит», пробуждение
из сна, отсчёт и список цитат.

Заодно — скрипты сборки и выпуска: номер сборки читается как дата и со
временем растёт, имя DMG и тег релиза берут версию из `Info.plist`, ворота
релиза не пускают невыросший номер, в описании релиза есть требования и
абзац про первый запуск, а фид обновлений собирается так, что приложение его
разбирает: кладёт его bash, читает Swift, и проверка у них общая. Скрипты
проверяются снаружи, запуском, — ровно так, как их зовут `build.sh`
и `release.sh`.

Обновление проверяется с двух сторон. Подпись EdDSA — что она сходится с
архивом, что подменённый архив её не проходит и что чужим ключом её не
подделать; подписывает прогон своим ключом, из связки ключей ничего не берётся.
Два фида — что адрес архива в них один, а имена файлов те же, что знает
приложение. И бандл со скриптами — что адрес фида установщика, выключенная
автопроверка и порядок подписи на месте.

Прогон — обычная программа, а не `swift test`: XCTest и swift-testing
поставляются только с полным Xcode, а собираться всё должно на одних Command
Line Tools. Тесты запускаются и внутри `./build.sh` перед сборкой бандла.

## DMG

```bash
./build.sh --dmg
```

Кладёт рядом с бандлом `Clepsydra-<версия>.dmg`: версия в имени — человеческая,
`CFBundleShortVersionString` из `Resources/Info.plist`, и берётся оттуда
скриптом `Tools/dmg-name.sh`, а не пишется в сборке руками.

Внутри — оформленное окно: слева иконка Clepsydra, справа ярлык Applications,
между ними стрелка и подпись «Перетащи в папку». Панель инструментов и боковая
панель скрыты, размер окна и позиции иконок заданы. Образ только для чтения и
сжат (UDZO).

Собирает `Tools/make-dmg.sh`. Фон рисует `Tools/make-dmg-background.swift` —
сразу в двух разрешениях, @1x и @2x, которые `tiffutil` складывает в один TIFF:
на retina Finder берёт из него нужное, и картинка не мылит. Размеры окна и
координаты иконок заданы в `Tools/make-dmg.sh` и оттуда уходят и в AppleScript,
и в рисовальщик аргументами: правится одно место, стрелка с иконками не
расходится.

Оформление ставит Finder по AppleScript, поэтому при первом прогоне macOS
спросит разрешение на автоматизацию, а на машине без графического сеанса
сборка DMG не пройдёт (см. [ADR-0008](adr/0008-dmg-window-is-dressed-by-finder.md)).

Обычный `./build.sh` DMG не делает: монтировать том и ждать Finder на каждой
сборке для разработки незачем.

Что человек увидит при первом запуске скачанного DMG — в [docs/install.md](install.md).

## Релиз

```bash
./release.sh 1.0
```

Ключей у команды нет: выпуск делается руками с машины автора, и подтверждения
он спрашивает с клавиатуры.

Одна команда: прогон тестов, сборка бандла и DMG, тег `v1.0` в `origin` и
черновик релиза на GitHub с образом и его суммой sha256.

Релиз уходит в `origin` — `ilya-pesterev/clepsydra`, туда же, куда код. Задачи
живут в другом репозитории, и релизы там ни при чём. Адрес выводит
`Tools/origin-repo.sh` из `origin` и сверяет с ожидаемым: перепутанный `origin`
отправил бы черновик с образом молча не туда.

**Версию называет человек**, и она сверяется с `CFBundleShortVersionString`
из `Resources/Info.plist` до всего остального. Релиз `v1.0` с бандлом версии
0.9 не создаётся: страница обещала бы не то, что покажет «О программе».
Поднимать версию — отдельный коммит перед выпуском.

**Что изменилось** пишется руками в `docs/releases/<версия>.md` и уходит в
описание релиза первым разделом. Файла нет — выпуска нет, и узнаётся это до
сборки, а не после. Требования и абзац про первый запуск дописывает
`Tools/release-notes.sh`: они от релиза к релизу не меняются, а забыть их
на странице проще всего.

**До публикации скрипт отказывается**, если:

- названная версия разошлась с бандлом (`Tools/release-tag.sh`);
- тег уже есть локально, в `origin` или как релиз на GitHub;
- в рабочем дереве есть незакоммиченные изменения — тег указал бы не на то,
  что выпускается;
- ветка не отправлена в `origin` — тег указал бы на коммит, которого там нет;
- номер сборки не больше номера прошлого релиза (`Tools/release-gate.sh`,
  те же ворота, что у `./build.sh --release`) — сверка идёт до сборки, чтобы
  сбитые часы не отваливали выпуск через десять минут после тестов;
- тесты не прошли — их прогоняет `build.sh` перед сборкой бандла.

**Что уехало в бандл, скрипт говорит вслух.** Портретов и фотографий в
репозитории нет, сборка берёт их с машины автора; если какая-то папка пустая,
скрипт называет, какой экран уйдёт без картинок, и ждёт подтверждения с
клавиатуры. Считает их `Tools/bundle-pictures.sh` — тот же, что печатает счёт
в `./build.sh`, чтобы сборка и выпуск не разошлись в цифрах.

**Релиз создаётся черновиком.** Пока он в черновике, файл уже можно скачать и
пройти установку целиком — это и есть проверка. Открыть людям — отдельный
явный шаг:

```bash
gh release edit v1.0 --repo ilya-pesterev/clepsydra --draft=false
```

Собранный образ подписан ad-hoc: Gatekeeper при первом запуске остановит, и
описание релиза честно рассказывает, как пройти этот путь. Нотаризованную
сборку делает `./build.sh --release --dmg` — см. [Раздача другим
людям](#раздача-другим-людям); `release.sh` её не выпускает.

После удачного выпуска номер релиза записывается в `last-release-build` —
файл нужно закоммитить.

Образ уходит в релиз под именем без версии — `Clepsydra.dmg`, — хотя рядом
собирается `Clepsydra-<версия>.dmg`. Оба имени печатает `Tools/dmg-name.sh`,
релизное — по ключу `--published`. Причина в первом пункте «Установки» в README:
он ведёт на `releases/latest/download/Clepsydra.dmg`, то есть скачивание
начинается сразу, без промежуточной страницы. Будь в имени версия, с выходом 1.1
эта ссылка отдавала бы 404, и README пришлось бы править каждый релиз. Какая
это версия, написано в заголовке релиза и в «О программе». Копия под релизным
именем живёт только до конца выпуска; собранный файл версию в имени сохраняет.

К релизу прикладываются образ и архив обновления, каждый со своей суммой
sha256, и два фида — `updates.json` для пункта меню, `updates.xml` для
установщика. Новый файл встаёт в список `artifacts` в `collect_artifacts` —
сумму ему посчитает тот же цикл; новый шаг выпуска — ещё одна строка в списке
шагов внизу `release.sh`.

Выпуск отказывается идти, если открытая половина ключа обновления в
`Resources/Info.plist` не от того ключа, которым подписывается архив, — см.
[«Ключ обновления»](#ключ-обновления).

## Обновления

Установленная копия узнаёт о новом выпуске из **фида** — файла `updates.json`,
который `Tools/update-feed.sh` кладёт в релиз рядом с образом:

```json
{
  "version": "1.1",
  "build": "20260904105921",
  "archive": "https://github.com/ilya-pesterev/clepsydra/releases/download/v1.1/Clepsydra.zip",
  "published": "2026-09-04T10:59:21Z",
  "notes": "## Что изменилось\n\n- …\n"
}
```

Что изменилось приходит тем же файлом `docs/releases/<версия>.md`, что и в
описание релиза: два разных списка изменений разошлись бы на первом же выпуске.

**Адрес фида постоянный** — `releases/latest/download/updates.json`, тот же
приём, что у образа в «Установке». Поэтому имя файла от релиза к релизу не
меняется: поменяйся оно, и установленные копии перестали бы находить фид.
Имя печатает сам скрипт (`./Tools/update-feed.sh --name`), а в приложении оно
живёт в `UpdateFeed.fileName` — тест сверяет, что это одна строка.

**Адрес архива в фиде ведёт на архив того самого выпуска**, а не на
`releases/latest`: фид описывает конкретную версию, и «последний» за время
между чтением фида и скачиванием успеет смениться. И не на образ: образ человек
монтирует и перетаскивает руками, а архив разворачивает установщик.

Приложение читает из фида два поля — версию и номер сборки; адрес архива, дата
и «что изменилось» лежат в нём для человека и для установки на месте. Неполный
фид ловит не установленная копия, которой чинить его нечем, а
`Tools/update-feed.sh` при выпуске.

Приложение спрашивает фид раз в сутки, молча, на том же тике, что считает
помидор, и показывает ответ пунктом меню: «Проверить обновления», «Установлена
последняя версия» или «Обновить до 1.1». Ни сети, ни ответа, ни разбора —
молчание. Сравнение идёт по `CFBundleVersion`, а не по человеческой версии;
почему проверка тихая и почему меню не считается обращением к человеку —
[ADR-0009](adr/0009-updates-are-checked-quietly.md).

Правила проверки — срок, сравнение, строка пункта — живут в `ClepsydraCore`
(`Updates`, `UpdateFeed`, `UpdateLabel`) и покрыты тестами; сеть и часы
остались в `UpdateChecker` рядом с AppKit.

## Установка на месте

Щелчок по «Обновить до 1.1» скачивает новую версию, заменяет ею установленную
и запускается уже новой. Ни браузера, ни перетаскивания, ни похода в
«Конфиденциальность и безопасность»: карантин ставится на скачанное браузером,
а подменённое установщиком приложение его не получает. Без сертификата это
единственный способ обновиться одним щелчком — почему так и чем за это
заплачено, в [ADR-0010](adr/0010-update-installs-itself.md).

Пока релиз лежит черновиком, ни фида, ни фида установщика по адресу
`releases/latest/download/` нет: GitHub их не отдаёт. Обновление оживает не в
момент выпуска, а когда черновик открывают людям, — как и ссылка на образ в
README.

Ставит **Sparkle**, версия 2.9.6, закреплённая точно в `Package.swift`.
Фреймворк приезжает готовым XCFramework — собрать его на одних Command Line
Tools нечем, — поэтому первая сборка требует сети. `build.sh` кладёт его в
`Clepsydra.app/Contents/Frameworks/`, выбрасывает XPC-службы (они нужны
приложению в песочнице, а Clepsydra не в ней) и подписывает изнутри наружу:
сначала вложенное в фреймворк, потом фреймворк, потом приложение.

Ad-hoc сборка подписывается **без** `--options runtime`, и это не забывчивость:
hardened runtime включает library validation, а у ad-hoc подписи нет Team ID,
и собственный фреймворк в бандле после такой подписи не грузится вовсе.
В релизной ветке `--options runtime` остаётся: там обе подписи от одного
Developer ID.

Окон установщик не открывает ни одного: `SPUUserDriver` реализован целиком, и
не показывает ничего ни один его метод — где Sparkle ждёт ответа, отвечаем «да»,
где ждёт окна, молчим (`Sources/Clepsydra/UpdateInstaller.swift`). Расписание
Sparkle выключено — проверяет обновления сама Clepsydra, раз в сутки и молча.
Не поставилось — открывается страница релиза, ровно как до установщика.

### Фид установщика

Sparkle читает свой файл — `updates.xml`, который кладёт
`Tools/update-installer-feed.sh` тем же шагом выпуска:

```xml
<item>
  <title>1.1</title>
  <sparkle:version>20260904105921</sparkle:version>
  <sparkle:shortVersionString>1.1</sparkle:shortVersionString>
  <sparkle:minimumSystemVersion>14.0</sparkle:minimumSystemVersion>
  <enclosure url="https://github.com/ilya-pesterev/clepsydra/releases/download/v1.1/Clepsydra.zip"
             length="11419994"
             type="application/octet-stream"
             sparkle:edSignature="…" />
</item>
```

Фидов два, потому что одним обойтись нельзя: Sparkle читает фид только по
`http`/`https` и схему `file://` отвергает явно — собрать фид на месте из уже
прочитанного `updates.json` и отдать его установщику невозможно. Адрес архива
в обоих один, и прогон это сверяет.

Описания выпуска в фиде установщика нет намеренно: окна с «что изменилось»
приложение не показывает, а второй список изменений однажды разошёлся бы с
первым.

Архив обновления — `Clepsydra.zip`, его собирает `Tools/update-archive.sh` через
`ditto` из того же бандла, что уехал в образ. Обычный `zip` потерял бы
символические ссылки внутри фреймворка, и подпись после распаковки не сошлась
бы.

### Ключ обновления

Подпись бандла ad-hoc, и проверить её установщику не по чему. Всё доверие
держится на ключе EdDSA: закрытая половина живёт в связке ключей на машине
автора, открытая едет в бандле в `SUPublicEDKey`. Архив с неверной подписью или
подменённый по дороге не ставится.

Ключ заводится один раз:

```bash
./Tools/sign-update.swift --create
```

Скрипт напечатает открытую половину — впишите её в `Resources/Info.plist` под
ключом `SUPublicEDKey` и закоммитьте. Второй раз ключ не заводится: перезапись
оставила бы все установленные копии без обновлений. Открытую половину можно
напечатать снова:

```bash
./Tools/sign-update.swift --public
```

Ключ лежит в связке ключей как обычный пароль: служба
`https://sparkle-project.org`, учётная запись `clepsydra`. Формат тот же, что у
Sparkle, — 32 байта семени в base64, — поэтому тем же ключом умеет подписывать
и `sign_update` из её поставки, если назвать ей учётную запись:

```bash
.build/artifacts/sparkle/Sparkle/bin/sign_update --account clepsydra Clepsydra.zip
```

Своей учётной записи она не знает и без флага ответит «Signing key not found».
Держим это как запасной путь, а не как основной: путь внутри `.build/` —
хозяйство SwiftPM, и меняться он может без предупреждения.

Байты подписи у двух утилит на одном файле **разные**, и это нормально: ed25519
допускает разный одноразовый множитель, а проверка обе принимает — каждая
утилита сходится с подписью другой, и открытая половина ключа у них одна.
Сравнивать подписи между собой нельзя, сверять надо проверкой.

Первый раз связка ключей спросит разрешение на доступ; это нормально, скрипт
не подписан.

`./release.sh` сверяет открытую половину в `Resources/Info.plist` с ключом из
связки **до сборки** и без совпадения не выпускает. Архив, подписанный ключом,
которого нет в бандле, не поставился бы ни на одну копию — и узналось бы это
после выпуска, когда чинить уже нечем.

**Если ключ потерян.** Восстановить его нельзя, и обновить установленные копии
больше нечем: они сверяют архив с той открытой половиной, что уехала в них, и
архив, подписанный новым ключом, отвергнут. Порядок действий в этот день:

1. завести новый ключ — `./Tools/sign-update.swift --create`;
2. вписать новую открытую половину в `Resources/Info.plist` и закоммитить;
3. выпустить версию как обычно;
4. в описании релиза написать, что эта версия ставится руками, из образа, — и
   что следующая снова будет обновляться сама.

Обновиться на месте с потерянным ключом нельзя ни в каком порядке: подпись
проверяет **старая** копия старым ключом, и уговорить её нечем. Поэтому ключ
стоит выгрузить из связки ключей и положить туда же, где лежат остальные
невосстановимые пароли.

## Раздача другим людям

Ad-hoc подпись Gatekeeper отклоняет — у друга приложение при первом запуске
заблокируется. Чтобы этого не было, нужен Apple Developer Program, сертификат
Developer ID Application и нотаризация.

Один раз сохраняем учётные данные в связку ключей:

```bash
xcrun notarytool store-credentials "clepsydra" --apple-id "you@example.com" --team-id "AB12CD34EF" --password "abcd-efgh-ijkl-mnop"
```

`--password` — не пароль от Apple ID, а app-specific password с appleid.apple.com.

Дальше каждая релизная сборка — одной командой:

```bash
./build.sh --release
```

Скрипт подпишет с hardened runtime и timestamp, отправит на нотаризацию,
дождётся вердикта, прикрепит тикет к бандлу и соберёт `Clepsydra.zip`.

Ключи складываются: `./build.sh --release --dmg` соберёт ещё и DMG, подпишет
его тем же сертификатом, нотаризует отдельно и проверит через `spctl`.
Gatekeeper смотрит на скачанный файл, а не только на приложение внутри него:
нотаризованный бандл в неподписанном образе даёт человеку ровно то окно, ради
которого весь релиз и затевался.

Если нотаризация образа не прошла, бандл к этому моменту уже нотаризован —
раздавать можно `Clepsydra.zip`, пока образ не починен.

Выпуск останавливается, если номер сборки не больше номера прошлого релиза:
последний выпущенный номер лежит в `last-release-build`, `--release` сверяется
с ним до сборки и переписывает после удачной раздачи — файл нужно закоммитить.
Ворота одни на двоих, `Tools/release-gate.sh`: `./release.sh` сверяется с тем
же файлом и пишет в него тот же номер.
Не выросший номер значит, что часы на машине сбились: обновление такой релиз
никому не покажет.

## Стек

SwiftPM + AppKit (`NSStatusItem`, `NSMenu`, `NSWindow`) + SwiftUI внутри
полноэкранного экрана. `LSUIElement`, минимум macOS 14.

Автомат состояний вынесен в отдельную библиотеку `ClepsydraCore` — без AppKit,
без таймеров и без обращений к системным часам: момент всегда приходит снаружи
параметром. Поэтому он покрыт тестами целиком.
